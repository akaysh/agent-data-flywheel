# RideCo Flywheel

ODSC West 2026 workshop: *Every AI agent needs a data flywheel.* One toy support agent
(router + 3 subagents, mock MCP tools, synthetic data) that you eval, judge, break, and improve.

Open `workshop.ipynb` (Colab works, no Docker needed). Set `OFFLINE = True` to replay
recorded LLM responses with no key or wifi.

## Layout

| Path | What |
| --- | --- |
| `scenarios/scenarios.yaml` | Source of truth for tasks. `regressions.yaml` is generated by the flywheel. |
| `scripts/make_tasks.py` | Renders scenarios into Harbor task folders under `tasks/` |
| `scripts/check_state.py` | Deterministic verifier (copied into every task) |
| `tools/` | Mock MCP tools (FastMCP). Enforce nothing, log every call to `tool_calls.jsonl` |
| `agent/` | LangGraph router + charges / lost item / account subagents |
| `sim/` | LLM-driven customer simulator (reads the hidden persona) |
| `runner/` | Docker-free runner for Colab. Same tasks, same verifier as Harbor |
| `harbor_adapter/` | Harbor agent adapter for `harbor run` on stage |
| `judge/` | Vague and good rubrics, judge runner, kappa vs expert labels |
| `flywheel/` | Failed traces to regression tasks, verdicts to DPO pairs and rewards |
| `llm/` | Chat model factory (any OpenAI-compatible endpoint) and the disk cache for `OFFLINE` |

## Run it

```bash
uv venv --python 3.12 .venv && uv pip install -r requirements.txt
cp .env.example .env   # fill in, or use OFFLINE=1
python scripts/make_tasks.py
pytest                 # no LLM needed
```

Eval and flywheel from the CLI (run from the repo root):

```bash
python -m scripts.run_eval --label before-fix --prompt-version v1 --judge good
python -m scripts.export_flywheel --traces data/traces/before-fix.jsonl
python -m scripts.make_label_sheet --traces data/traces/*.jsonl   # expert labeling
```

On stage, with Docker (Harbor task format is the source of truth):

```bash
harbor run -p tasks -a oracle                      # every task must score 1
harbor run -p tasks --agent-import-path harbor_adapter.rideco_agent:RideCoAgent -n 4
```

## Offline mode and the cache

`OFFLINE=1` replays `cache/` and never calls out: no key, no wifi. The cache key is the model,
temperature, and the *content* of each message, not the endpoint or message metadata, so
a response recorded through a gateway replays anywhere. `cache/_models.json` records which model
each role used. A request that was never recorded raises `CacheMissError`.

Re-record after changing any prompt, tool, task, or rubric: run the notebook with `OFFLINE=0`
(headless: `OFFLINE=0 jupyter nbconvert --to notebook --execute workshop.ipynb`), then replay it with
`OFFLINE=1 CACHE_HIT_LOG=/tmp/hits.log`, and prune with `llm.cache.prune_unused("cache", "/tmp/hits.log")`.
Delete `scenarios/regressions.yaml`, `tasks/regression-*` and `data/export/` first so the run
starts from the same state attendees see.

## Models

| Role | Env | Used for |
| --- | --- | --- |
| agent | `AGENT_MODEL` | the shipped (v1) agent, small on purpose |
| fixed_agent | `FIXED_AGENT_MODEL` | the "swap the model" fix |
| simulator | `SIM_MODEL` (defaults to `AGENT_MODEL`) | the simulated customer |
| judge | `JUDGE_MODEL` | LLM judge |

### Bring your own provider

Set `OFFLINE = False` in the notebook (or `OFFLINE=0`) and give it your provider's endpoint and a key.
The code speaks the OpenAI chat format, which most providers expose, so you don't need an OpenAI
account. Bedrock, Azure OpenAI and Vertex need a proxy such as LiteLLM in front. The model must support tool calling. We have only tested through Lyft's gateway;
the other rows are the documented endpoints, not combinations we ran.

| Provider | `LLM_BASE_URL` |
| --- | --- |
| OpenAI | `https://api.openai.com/v1` |
| Groq | `https://api.groq.com/openai/v1` |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Anthropic (compatibility endpoint) | `https://api.anthropic.com/v1/` |
| Ollama (local) | `http://localhost:11434/v1` |

- Pick a small model for `AGENT_MODEL` and a stronger one for `FIXED_AGENT_MODEL` and `JUDGE_MODEL`.
- Reasoning models reject `temperature=0`: set `LLM_TEMPERATURE=none`.
- Your numbers will differ from the recorded run. A careful model may not trip the planted bugs.
- A full live run is hundreds of calls. Free tiers may rate-limit. Live runs write new files into
  `cache/`; don't commit them.
- Keys stay in the environment or `.env` (gitignored). Never paste them into the notebook source.

## What the agent versions are

`v1` is a deliberately weakened prompt (policy partly dropped, "be decisive, tell the customer it is
taken care of") and a router that picks one agent. It reproduces the planted bugs with a small model.
`v2` restores the policy and lists every needed agent. With the **same small model**, v2 still fails:
the model says "I've escalated this" without calling `escalate_to_human`. A stronger model fixes it.

## Expert labels: read this before the talk

`data/expert_labels.csv` was produced by **Claude Opus subagents**, not human experts (see the
`labeler` column). They were given the policy and the written guidelines, and never saw judge
verdicts. The guidelines were calibrated three times against these same 45 traces, so any kappa you
get from them is optimistic, and 45 traces with few failures per criterion gives noisy kappas.
Replace with real SME labels (`scripts/make_label_sheet.py` makes the sheet) and rerun
`python -m scripts.score_judges` before quoting numbers on stage.
